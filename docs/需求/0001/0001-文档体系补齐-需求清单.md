# 0001 文档体系补齐-需求清单

> 需求编号：0001
> 项目：LoopForge
> 状态：已交付
> 创建日期：2026-11-25
> 证据基线：`develop` @ `6833a9fb`

## 1. 背景

仓库已有中英双语 README、部署手册与 API 契约，但缺少交接所需的索引、架构全景、功能清单、术语表、版本化流程文档与文档门禁；历史文档散落在 `docs/` 根目录、`docs/testing/`、`docs/proposals/`，无法按统一规则维护。

## 2. 目标

1. 建立 `docs/` 固定五位置：`README.md`、`架构全景图.md`、`需求/`、`流程/`、`功能/`。
2. 覆盖全部功能点：接口、MCP 操作、执行机器协议、后台任务与业务链路。
3. 流程图、时序图、状态机全部使用 Mermaid 内嵌并可实际渲染。
4. 旧散文档按内容归类迁入五目录，更新所有引用链接。
5. 提供可复跑的文档门禁，并在 CI 之外可本地执行。

## 3. 范围

### 3.1 包含

| 类别 | 内容 |
| --- | --- |
| 架构 | 系统上下文、部署拓扑、管理变更与 SOP 运行链路 |
| 功能 | 01 项目架构、02 功能清单、03 领域术语表、04 接口附录、05–14 专题 |
| 流程 | 01 登录与账号 至 14 平台管理与信任主机，均 `-v1` |
| 索引 | `docs/README.md`、根 README 入口、`AGENTS.md` 阅读顺序 |
| 工具 | `.skills/project-docs-bootstrap/scripts/check-docs.mjs`（含 `--ignore`） |

### 3.2 不包含

- 不改业务代码、数据库结构与对外接口契约。
- 不把历史提案转换为需求文档。
- 不重命名代码中的领域对象或表字段。

## 4. 验收标准

| 编号 | 标准 |
| --- | --- |
| A1 | `docs/` 根只有 `README.md`、`架构全景图.md`、`功能/`、`流程/`、`需求/` 与声明的资产例外 |
| A2 | 功能文档 14 篇、流程文档 14 篇，编号连续、H1 与文件名一致 |
| A3 | 每篇流程文档含 flowchart、sequenceDiagram、stateDiagram-v2 |
| A4 | 文档门禁 0 失败；全仓库 Markdown 链接 0 断链 |
| A5 | Mermaid 全部文档实际渲染成功 |
| A6 | 根 README、CONTRIBUTING、CHANGELOG、e2e 说明中的旧路径全部更新 |
