# 0001 文档体系补齐-方案评估

> 需求编号：0001
> 项目：LoopForge
> 状态：已交付
> 证据基线：`develop` @ `6833a9fb`

## 1. 问题拆解

需要同时解决四类问题：文档结构不合规、缺少可交接内容、图与代码不同步、缺少可复跑校验。四类问题互相制约：只补内容不重组，链接会继续漂移；只重组不补内容，门禁仍无实质校验对象。

## 2. 备选方案

| 方案 | 描述 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A 维持现状 + 补索引 | 保留散文档，只写 `docs/README.md` | 改动最小 | 结构仍不合规，链接持续漂移，无法门禁 | 不采用 |
| B 严格五目录重组 | 新建五位置，旧文档合并归类，统一改链 | 符合技能规范，可门禁、可交接 | 一次性改动量大，需逐条验证链接 | 采用 |
| C 单文件大全 | 所有内容合并为一份超长文档 | 链接最少 | 难维护、难评审，流程无法版本化 | 不采用 |

## 3. 关键决策

| 决策 | 选项 | 采用 | 理由 |
| --- | --- | --- | --- |
| 覆盖范围 | 核心链路 / 模块主流程 / 全部功能点 / 仅接口 | 全部功能点 | 用户确认；接口、MCP、Runner、后台任务均可统计 |
| 图表格式 | Mermaid / Mermaid+SVG / Draw.io | Mermaid 内嵌 | GitHub 原生渲染，改动可评审，无需额外产物 |
| 组织方式 | 严格五目录 / 保留部分 / 只新增 | 严格五目录 | 与技能门禁一致；例外仅限代码资产与子项目手册 |
| 异常深度 | 仅主流程 / 主流程+关键异常 / 全量补偿 | 主流程+关键异常 | 覆盖失败、超时、审批、沙箱与外部依赖分支 |
| 旧文档处理 | 合并 / 拆分 / 原样保留 | 按主题合并 | 减少重复，保留原文作为正文，迁移说明记录来源 |

## 4. 例外判定

| 路径 | 判定 | 依据 |
| --- | --- | --- |
| `docs/api` | 保留 | Go 包 `apidocs` 通过 `go:embed` 编译进二进制，移动会断编译 |
| `docs/assets` | 保留 | README 图片与提案 HTML 资源，不属于文档正文 |
| `docs/local` | 保留 | Local 子项目手册，等同服务级文档，被 `local/README.md` 引用 |
| `docs/需求` | 新建 | 本需求为首个按五件套登记的需求 |

## 5. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 批量改链误伤代码块或外部链接 | 链接解析只处理 Markdown 目标，代码围栏与 http/# 前缀跳过 |
| 合并后锚点失效 | 保留原标题文本，仅降级标题层级；迁移后全仓链接检查 |
| 门禁对例外目录误报 | 固化脚本并增加 `--ignore`，例外在索引中公开说明 |
| 迁移丢失原文 | 合并文档保留原文正文，迁移说明列出全部来源文件 |
| 文档与代码漂移 | 记录基线 commit、统计复算命令与门禁命令 |
