## 1. 仓库分层

- `internal/repo`：每个领域一个 Repo；`Store` 只组合 Repo 与连接生命周期，禁止新增领域方法。
- `internal/httpapi`：每个领域一个 handler struct；新领域必须新建 handler，不得挂到现有领域或 `Server`。
- 领域间协作用显式指针注入，禁止循环依赖。
- `repo.Open()` 只做连接与 AutoMigrate；数据迁移与 seed 一律写 `migrations/` 手动执行。

## 2. 常用命令

```bash
# 本地运行（Go 1.26.11+）
make run

# 单元测试（并行 16，超时 4 分钟）
make test

# 覆盖率门禁（Go/前端/Web/E2E）
make coverage

# 构建全部二进制与前端
make build

# 单独构建对话前端
make build-chatbot

# 原生开发脚本（配置密钥、起 MySQL、构建并启动 8090）
bash scripts/dev.sh

# 容器安装/源码构建
./start.sh          # 发布镜像
./start.sh dev      # 当前源码构建
```

## 3. 测试与验证

- 修改后端：至少运行受影响包的 `go test`；全量 `make test` 依赖 MySQL 时先确认环境。
- 修改前端：`npm --prefix chatbot run build`（或 `make build-chatbot`），并在浏览器实际走通受影响页面。
- 修改文档：运行文档门禁（见第 5 节），并对 Mermaid 做实际渲染校验。
- 修复 bug 补回归测试；不得为变绿删除断言或跳过用例。
- 交付时给出实际执行的命令与结果；未执行项明确列出。

## 4. 编码与安全

- 新路由必须处理鉴权、参数校验与错误响应；不允许匿名绕过默认鉴权。
- 凭据只通过配置/环境注入，不写入代码或文档；日志不得新增明文密钥。
- 破坏性操作（删除数据、重置密码、改共享配置）先确认再执行。
- 前端改动先读 `design.md`，沿用布局、图标、动效与主题约定。
- 生成代码（`*.pb.go`、构建产物）不手改。

## 5. 文档体系

- `docs/` 固定五个位置：`README.md`、`架构全景图.md`、`需求/`、`流程/`、`功能/`。
- 例外（保留原路径）：`docs/api`（`apidocs` Go 包与 `openapi.yaml` 嵌入资产）、`docs/assets`（README 图片）、`docs/local`（Local 子项目手册）。
- 功能文档命名 `{两位编号}-{中文名称}.md`；流程文档 `{两位编号}-{中文名称}-v{N}.md`；首页标题与文件名、文档头编号/版本一致。
- 只有流程变化才新增流程版本；格式、错别字、链接在当版修正，历史版本只读。
- 新文档必须写入 `docs/README.md` 索引；索引不得留悬空链接。

## 6. 文档门禁

```bash
node .skills/project-docs-bootstrap/scripts/check-docs.mjs \
  --docs docs --flow-dir 流程 \
  --require-flow-diagrams --require-status --require-evidence \
  --ignore api --ignore local --ignore assets
```

检查项：命名与编号、H1/文档头一致性、本地链接、表格列数、流程图三种图（flowchart/sequenceDiagram/stateDiagram-v2）、状态与证据基线字段。

## 7. Git 与提交

- Conventional Commits；中文描述。
- 只有用户明确要求时才提交；推送需单独授权。
- 提交前检查 `git status` 与 `git diff`，只暂存本次相关文件。
- 删除/重命名前检查脚本、文档与代码引用。
