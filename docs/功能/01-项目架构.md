## 1. 定位与技术栈

LoopForge 是自托管的编码 Agent 编排平台：把需求、SOP（步骤图）、模型 CLI、沙箱与人工审批串成可追踪的交付链路。仓库同时保留旧版本地工作流运行时 `local/`（Legacy）。

| 维度 | 事实 | 证据 |
| --- | --- | --- |
| 后端语言 | Go 1.26.11，模块名沿用上游 `agentflow` | `go.mod` |
| HTTP 框架 | Gin 1.12 | `go.mod`、`internal/httpapi/server.go` |
| ORM | GORM 1.31 + MySQL 驱动 | `go.mod`、`internal/repo/repo.go` |
| 数据库 | MySQL 8.4（唯一数据源；测试可用 sqlite） | `compose.yaml`、`internal/repo` |
| 前端 | React 19 + Vite（`chatbot/` 编译进 `web/native-chat/`）；`web/` 为内嵌上游界面 | `chatbot/package.json`、`Dockerfile` |
| 实时通信 | WebSocket（运行流、Runner 控制、终端） | `internal/httpapi/stream.go`、`runner_ws.go` |
| 消息渠道 | 企业微信、飞书（Lark SDK）、钉钉（Stream SDK） | `go.mod`、`internal/botinteraction/` |
| 容器 | 沙箱由宿主机 Docker 启动 | `compose.yaml`、`internal/runtime/` |
| 观测 | OpenTelemetry / OTLP 可选 | `internal/observability/` |

## 2. 进程与入口

| 入口 | 文件 | 类型 | 端口/触发 | 职责 |
| --- | --- | --- | --- | --- |
| 平台主进程 | `cmd/agentflow/main.go` | HTTP + 后台执行 | 容器内 `:8080`，宿主 `${AGENTFLOW_HTTP_PORT:-8090}` | `-role api` 只提供 API；`worker` 只执行；`all`（默认）两者兼有 |
| 执行机器 | `cmd/agentflow-runner/main.go` | 常驻守护进程 | 出站连接平台 | 注册、心跳、拉取任务、在本地沙箱执行、上报事件 |
| 公共 MCP | `cmd/agentflow-mcp/main.go` | stdio MCP | 由客户端启动 | 把 111 个公共操作暴露为 MCP 工具 |
| 门禁 MCP | `cmd/agentflow-gate-mcp/main.go` | stdio MCP | 由沙箱/脚本调用 | 结构化校验结果输出 |
| 账号工具 | `cmd/loopforge-account/main.go` | 一次性 CLI | 手动执行 | 从 stdin 读密码创建/重置本地账号，可授予平台管理员 |

平台进程关键参数（`cmd/agentflow/main.go`）：

| 参数 | 作用 |
| --- | --- |
| `-addr` | HTTP 监听地址，覆盖 `AGENTFLOW_HTTP_PORT` |
| `-role` | `api`、`worker` 或 `all`（默认） |
| `-workspaces` | 沙箱工作区根目录（compose 传入 `LOOPFORGE_DATA_DIR/workspaces`） |
| `-worker-concurrency` | 本 worker 并发沙箱节点数，默认 8 |
| `-mysql-dsn` | MySQL DSN，覆盖 `AGENTFLOW_MYSQL_DSN` |
| `-mcp-token` | MCP 网关 Bearer Token，或 `AGENTFLOW_MCP_TOKEN` |
| `-cli-action` / `-credential-action` | 管理型一次性动作，执行后退出 |

## 3. 分层与目录职责

```text
cmd/                 # 进程入口
internal/
  httpapi/           # 每个领域一个 handler struct
  engine/            # SOP 图、节点调度、租约、沙箱生命周期、交付
  repo/              # 每个领域一个 Repo（GORM）
  runtime/           # 执行器协议、沙箱、工具链
  runner/            # 执行机器协议与守护进程
  tracker/           # 远程 Issue/PR/MR 适配
  schedule/          # 定时任务
  notification/      # 通知渠道与投递
  botinteraction/    # 渠道 Bot 交互
  knowledge/         # 知识库
  preview/           # 预览产物
  mcpserver/         # MCP 协议实现
  application/       # 公共操作清单（MCP 工具来源）
  domain/            # 领域模型
web/                 # 内嵌 Web 界面
chatbot/             # 对话前端源码（构建为 web/native-chat）
local/               # 旧版本地工作流运行时（Legacy）
migrations/          # 手动执行的数据迁移 SQL
docs/                # 文档体系
```

分层规则（来自仓库 `AGENTS.md`，属当前有效约束）：

- `Store` 只组合各领域 Repo 与连接生命周期，禁止在 `Store` 上新增领域方法。
- 每个领域一个 Repo 与一个 handler struct；新领域必须新建，不得挂到现有领域。
- 领域间协作通过 `newStore` 或 `Server` 中的显式指针注入，禁止循环依赖。
- `repo.Open()` 只做连接与 gorm AutoMigrate；数据迁移与 seed 一律写 `migrations/` 手动执行。

## 6. 启动顺序

1. Compose 启动 MySQL，健康检查通过（`mysqladmin ping`）。
2. 平台容器启动，`repo.Open()` 连接 MySQL 并执行 AutoMigrate 增量 DDL。
3. 平台 healthcheck 请求 `/api/health`，通过后安装脚本执行 schema extensions 与起始目录（sandbox、SOP、体验项目）。
4. `role=api` 提供 HTTP；`role=worker` 领取节点租约并启动沙箱；`role=all` 同时承担两者。
5. 执行机器（可选）注册、心跳并领取任务；渠道 Bot 与定时任务在后台 worker 中运行。
6. 首次访问创建的第一个账号自动成为平台管理员。

## 7. 关键不变量

- `AGENTFLOW_AUTH_REQUIRED=true` 是默认安装的鉴权前提；只有 setup/register/登录与 health 等少数端点匿名可达。
- `AGENTFLOW_SESSION_SECRET` 必须跨重启与多实例保持一致，否则会话失效。
- 代码中不做数据迁移与 seed；`migrations/` 脚本由运维手动执行。
- 平台容器访问 Docker socket 等价宿主机 root；只部署在可信团队。
- 前端资源嵌入 Go 二进制；UI 改动必须重建镜像并强刷浏览器。
