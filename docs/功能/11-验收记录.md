### 托管 CI 后续处理 — 2026-10-16

首次托管运行暴露出与本地评审环境的三处差异：无检出（no-checkout）的 E2E 门禁继承了并不存在的 `local/` 工作目录；Node 22 把 API 目录当作模块解析，而不是发现其中的测试文件；Git 2.55 在没有任何合格索引条目时拒绝了已跟踪文件的暂存。现在门禁在 runner 的临时目录中运行，同时保留其失败检查；API 启动器显式指定 `*.test.mjs`；仅当不存在合格的已跟踪条目时才跳过暂存更新，并保留排除配置与常规错误处理。回归测试覆盖空检出、仅含被排除项的检出，以及源码的新增、更新与删除。

Node 22 API 验收通过 **100 个测试、13 个跳过、0 个失败**。在本地构建 Git 2.55 后，原实现复现了托管环境中的 pathspec 失败；修正后的 Git 测试以及 `TestGateExecutionScopeIsExplicit` 的五次重复运行均通过。托管的全新安装任务此前已独立通过。本地证据位于被忽略的 `.local/ci-node22-api.log`、`.local/ci-git-before.log` 和 `.local/ci-git255-full-go.log`。这些结果是对此前提交检查的补充；当前托管提交仍必须通过其自身的任务。

在 Docker 修复之后，托管的 API 与广度 UI 检查通过。公开 UI 检查随后暴露出一个夹具差异：原生任务中由管理后台预置的无密钥用户缺少欢迎项目成员身份，与自助注册用户不同。CI 现在通过常规注册端点预置该账号，并同时校验普通用户状态与欢迎项目成员身份。确切的工作流注册代码以及五个受影响的参考/演示浏览器用例，针对一个全新的验收账号通过。此改动仅影响测试预置；项目授权仍然强制执行。证据：被忽略的 `.local/ci-signup-browser.log`。

### 资源缓存升级

`web/index.html` 中的字面查询串并不是发送给浏览器的 URL。`studioFileServer` 在每次 HTML 请求时调用 `stampStudioIndex`。每个 CSS 与 JavaScript 引用都会用资源 SHA-256 哈希的前八个字节重写。HTML 以 `Cache-Control: no-cache` 提供；结果带版本的资源使用 `public, max-age=31536000, immutable`。

Chromium 检查保持同一浏览器上下文并启用了其 HTTP 缓存：

1. 一个同源 HTTP 代理提供先前的样式表及其内容哈希 URL，同时把认证、运行 API、流式与其他资源转发给真实平台。基线是本次改动之前的样式表。
2. 第二次常规文档导航复用了那个旧样式表。Chromium 的 DevTools 协议报告缓存命中；两次导航中代理只为旧资源收到一次请求。
3. 随后代理原样转发平台当前的 HTML。一次常规导航拉取了新的样式表 URL，既有的缓存样式表没有阻止任一动画出现。未使用清缓存、强制刷新、Playwright 请求路由或模拟的运行响应。

| 资源 | 提供的 URL | 网络请求 |
| --- | --- | --- |
| 先前的 CSS | `/observability.css?v=b5623289d4bd5745` | 1 次，随后从缓存复用 |
| 动效 CSS | `/observability.css?v=e10036f176cdcba1` | 升级后 1 次 |

样式表哈希跟随其字节内容，会随之后的编辑变化。手写的 `v=20261031metrics2` 在本次检查全程未变。`internal/httpapi/studio_test.go` 中的回归测试还验证：仅修改 CSS 即可改变所提供的 URL，而无需编辑 HTML 或重建 handler。

### 5D. 节点向会话提问（2026-11-20 追加）

按验收负责人要求：SOP 任意节点需要补充信息时，问题发到运行对应的飞书、钉钉会话；会话里的回答提交给同一个运行的同一个节点后继续执行。IM 和平台页面处理同一个待答节点，已经回答、节点结束或运行取消后不能再提交，回答时检查发言人的项目权限（手册第 8.8 节）。启动前澄清的项目／SOP 开关不在本次范围，已撤回。

自动化：群里发起的运行，节点提交 `human` 决定后，群里收到“节点需要补充信息”、问题和回答方式（飞书、钉钉各一遍，钉钉不提示引用），卡片“待处理”为问题；成员 @ Bot 发“回答：…”后，原运行原节点带着答案回到待执行，答案写入节点反馈和人工补充上下文，运行数不变，卡片失效；同一问题第二次回答（引用或“回答：”）被拒绝，平台先回答后群里回答被拒绝；运行取消后被拒绝；未绑定成员收到绑定链接，只读成员被拒绝，节点不变；飞书引用问题消息不加前缀也算回答，几个问题时列出编号并用“回答 1：”选择；单聊发起的问题发给发起人，只能在他的单聊里回答；普通消息不算回答。飞书问题卡片只有答案输入框和“提交答案”（表单提交），空答案在卡片上被拒绝，提交后卡片锁定并显示答案，答案经卡片提交到原节点、第二次提交被拒绝；企业微信的问题改为文字消息（SOP 通知和发回发起会话两条路径都不发卡片），引用这条消息回复即可回答。
